## Overview

`Ladder` is a session-oriented proxy manager for macOS and Linux.
It wraps `mihomo` with a friendly CLI, TUI, subscription management, and shell environment integration.

The active v2 implementation lives in `ladder-core/`.
The legacy shell-only version is preserved in `1.0/`.

## Features

- 🚀 **Multi-subscription** — manage multiple airport subscriptions simultaneously
- 🖥️ **TUI** — interactive node switcher with speed test and auto-best selection
- 🐚 **Shell integration** — `source env.sh` transparently sets and unsets proxy env vars in the current shell
- 📦 **Two release flavors** — external (small) or bundled (embeds `mihomo`, zero external dependency)
- 🍎 **macOS + Linux** — full support for both platforms, including Apple Silicon
- 🔒 **Watchdog** — automatically stops the proxy when the parent shell exits

## Quick Start

### 1. Download

From [Releases](https://github.com/ddddavid/ladder/releases), download the binary matching your platform:

- `ladder-core-linux-amd64`
- `ladder-core-linux-arm64`
- `ladder-core-macos-amd64`
- `ladder-core-macos-arm64`
- or the `ladder-core-bundled-*` variants

```sh
# Example: Linux amd64
curl -L https://github.com/ddddavid/ladder/releases/latest/download/ladder-core-linux-amd64 -o ladder-core
chmod +x ladder-core
mv ladder-core ~/.local/bin/
```

### 2. Install shell integration

`env.sh` is generated by the binary itself, so there is no separate script asset to download.

```sh
# Writes ~/.config/ladder/env.sh and prints the source command for your shell
ladder-core install

# Then add it to your shell rc manually
# zsh example:
echo 'source ~/.config/ladder/env.sh' >> ~/.zshrc
source ~/.zshrc
```

### 3. Add subscriptions

```sh
ladder sub add "https://your-airport-url.com/sub?token=xxx" --name AirportA
ladder sub add "https://another-airport.com/sub?token=yyy" --name AirportB
ladder sub list
```

### 4. Start proxy

```sh
# Start proxy and set env vars in the current shell
ladder start --env

# Start with a specific subscription only
ladder start -s AirportA --env

# Start multiple subscriptions
ladder start -s AirportA -s AirportB --env
```

### 5. Use TUI

```sh
ladder tui
```

### 6. Stop proxy

```sh
# Stop proxy and clear env vars
ladder stop --env

# Only clear env vars (proxy keeps running)
ladder unenv

# Only apply env vars (proxy already running)
ladder env
```

## CLI Reference

| Command | Description |
|---------|-------------|
| `ladder start` | Start proxy with all subscriptions |
| `ladder start --env` | Start proxy and apply shell env vars |
| `ladder start -s NAME` | Start with a specific subscription |
| `ladder start --auto-best` | Start and auto-select the lowest latency node |
| `ladder stop` | Stop proxy |
| `ladder stop --env` | Stop proxy and unset shell env vars |
| `ladder env` | Apply proxy env vars to the current shell |
| `ladder unenv` | Unset proxy env vars while keeping proxy running |
| `ladder tui` | Open the interactive TUI |
| `ladder status` | Show proxy status |
| `ladder sub add URL` | Add a subscription |
| `ladder sub list` | List subscriptions |
| `ladder sub remove NAME` | Remove a subscription |
| `ladder update` | Force update subscriptions |
| `ladder install` | Install shell integration |

## Configuration

Config file: `~/.config/ladder/config.toml`

```toml
[ladder]
port = 7890          # HTTP proxy port
socks_port = 7891    # SOCKS5 proxy port
control_port = 9090  # Mihomo REST API port
# api_secret = "your-secret"  # optional
# mihomo_bin = "/usr/local/bin/mihomo"  # optional, auto-download if not set

[[subscriptions]]
name = "AirportA"
url = "https://sub.airport-a.com/..."
interval = 86400

[[subscriptions]]
name = "AirportB"
url = "https://sub.airport-b.com/..."
interval = 43200
```

## How Shell Integration Works

`env.sh` provides a `ladder` shell function and works with POSIX-style shells such as `bash`, `zsh`, and `dash`.

When you call commands with `--env`, the function runs `eval "$(ladder-core ...)"`, which evaluates the exported environment variable statements directly in the current shell.

```sh
# What ladder start --env actually does internally
eval "$(ladder-core start --env --shell-pid $$)"
# Which sets: HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, http_proxy, https_proxy, all_proxy, NO_PROXY, no_proxy
```

---

## Watchdog

When started with `--env` (which passes `--shell-pid $$`), `ladder-core` monitors the parent shell PID:

- **Linux**: checks `/proc/{pid}/status`
- **macOS**: uses `kill(pid, 0)`

If the shell exits, the proxy is automatically stopped within about 2 seconds.
